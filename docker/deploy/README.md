# Deployment: laravel-reports.private-net.ch

The demo runs as its own container next to `website3` on the same server.
It does **not** terminate TLS and publishes **no** host ports: the existing
Caddy reverse proxy in `website3` owns the domain and forwards to `docs:80`
over a shared Docker network.

```
Internet -> :443 (Caddy in website3) -> laravel-reports.private-net.ch
                                     -> docs:80 (this stack)
```

## Why a separate container

The demo needs Chromium for PDFs, which is heavy and restart-prone. Keeping it
out of the `website3` container means a demo deploy never restarts the booking
site, and a website deploy only interrupts the demo for the few seconds the
shared proxy restarts.

## 1. DNS

Create an `A` (and optionally `AAAA`) record:

```
laravel-reports.private-net.ch  ->  <server IP>
```

Caddy fetches the certificate on the first request via HTTP-01, so port 80 must
be reachable from the internet.

## 2. Image

The image is built by `.github/workflows/deploy.yml` on every `v*` tag and
pushed to:

```
ghcr.io/guggach/laravel-reports-doc-demo:latest
```

The build context contains **both** repositories, because the demo consumes the
package through a Composer path repository. `docker/build.sh` assembles that
context locally:

```bash
# expects ../laravel-reports (like the README describes)
./docker/build.sh
./docker/build.sh --push

# or point at another checkout
PACKAGE_DIR=/src/laravel-reports ./docker/build.sh
```

## 3. First install on the server

```bash
mkdir -p /opt/laravel-reports
# copy docker/deploy/* into /opt/laravel-reports
cd /opt/laravel-reports

# optional: attach the running website3 app container to the shared network
./install.sh <website3-app-container>
```

`install.sh` creates `.env` (with a generated `APP_KEY`), `deploy.env`, the
`edge` network and starts the container. The image is public, so no GHCR token
is needed; only set `GHCR_TOKEN` in `deploy.env` if the package becomes private.

## 4. Route the domain through the existing Caddy

The Caddy in `website3` has to reach `docs:80`. Attach its app container to the
shared network once:

```bash
docker network connect edge <website3-app-container>
```

Add `edge` to the `app` service in the `website3` compose file as well, otherwise
the attachment is lost on the next website deploy:

```yaml
services:
  app:
    networks: [internal, edge]

networks:
  edge:
    external: true
```

Then add the block from `Caddyfile.snippet` to the Caddyfile of `website3` and
reload — no restart, no downtime:

```bash
docker compose exec app caddy validate --config /etc/caddy/Caddyfile
docker compose exec app caddy reload   --config /etc/caddy/Caddyfile
```

## 5. Updates

```bash
cd /opt/laravel-reports && ./pull.sh
```

`pull.sh` logs in, pulls `latest`, recreates the container, waits for `/up` and
then regenerates the screenshots and the prebuilt PDFs inside the container.
Add it to cron if you want automatic updates:

```cron
*/30 * * * * /opt/laravel-reports/pull.sh >> /opt/laravel-reports/deploy.log 2>&1
```

## What is stateful?

Nothing. The SQLite demo database is baked into the image, sessions and cache
use the `file` driver, logs go to stderr. `docker compose down` removes
everything; the next deploy rebuilds it.

The only files written at runtime are:

- `storage/app/demo-pdfs/*.pdf` (prebuilt PDFs)
- `public/images/examples/*.webp` (landing page screenshots)

Both are regenerated by `pull.sh`. If generation fails, the app still works:
the PDF route falls back to live Chromium rendering and the landing page shows
a placeholder.

## Resource limits

Chromium is the only hungry part. `compose.yml` caps the container at 1.5 GB
RAM, 1.5 CPUs and 512 PIDs. If PDF generation gets OOM-killed, raise
`mem_limit` first.

## Troubleshooting

```bash
docker compose ps
docker compose logs -f docs
docker compose exec docs php artisan demo:assets --url=http://127.0.0.1
docker compose exec docs curl -fsS http://127.0.0.1/up
```

If the domain returns 502, check that both containers are on the `edge`
network:

```bash
docker network inspect edge --format '{{range .Containers}}{{.Name}} {{end}}'
```

If the certificate is not issued, check that DNS points to the server and that
port 80 is reachable.
